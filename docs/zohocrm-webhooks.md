# Zoho CRM Webhook Integration - Baton

## Overview

Zoho CRM sends notifications to Baton whenever records are created / updated / deleted in the CRM (Deals, Contacts, Leads, Accounts, etc.). Baton normalizes them into events like `deals.created` and runs them through the rule engine, which triggers the target Docusign Workflow Builder workflows.

Webhooks are received via the **App Webhook**:

| URL | Authentication | Setup |
|-----|----------------|-------|
| `/api/webhooks/app/:webhookKey` | **Basic Auth** (username + password) | "out of the box" via the app install wizard in the UI |

This is exactly the path that the "Install Zoho CRM" wizard opens in the interface.

---

## ⭐ Most important: where to get the username and password

**You don't "get" them - you make them up yourself.**

The **Basic Auth Username / Password** fields in the Baton form are **not your Zoho account login**. They are an arbitrary credential pair that you:

1. **make up yourself** (any values - e.g. `baton-zoho` / a long random string as the password),
2. enter into the Baton form while installing the app,
3. and then enter **the same values** in the webhook settings on the Zoho CRM side.

The point: Basic Auth on an **inbound** webhook means "whoever knocks on this URL (Zoho) must prove it's really them" - via a username/password pair known only to you and Baton. This is stated explicitly in the app catalog ([app-catalog.ts:145](../baton/src/lib/app-catalog.ts#L145)):

> *"Create a username and password for this webhook. These are not your Zoho login - choose any values you like."*

## Setup

### Step 1. Install the Zoho CRM app in Baton

1. **Apps** page → find **Zoho CRM** → **Install**.
2. The wizard immediately generates and shows a **Webhook URL** like:
   ```
   https://your-domain.com/api/webhooks/app/<webhookKey>
   ```
   (the URL is generated by the preflight step before saving - [apps.ts preflight](../baton/src/routes/apps.ts#L75)). Copy it.
3. In the **Basic Auth Credentials** fields, enter the **made-up** username and password (see the section above).
4. Give the app a name and click **Install**.

What happens under the hood: the frontend joins the credentials into a `username:password` string ([InstallAppWizard.tsx:80](../baton-front/src/components/apps/InstallAppWizard.tsx#L80)), and the backend encrypts it into `secretKeyEnc` on the app record ([apps.ts:201](../baton/src/routes/apps.ts#L201)).

### Step 2. Configure the webhook in Zoho CRM

(steps from [setupInstructions](../baton/src/lib/app-catalog.ts#L144-L149))

1. Zoho CRM → **Setup → Developer Space → Webhooks** → **Configure Webhook**.
2. In the **Webhook URL** field, paste the URL from Step 1.
3. Method: **POST**.
4. Enable **Basic Authentication** and enter the **same** username/password as in Step 1.
5. Configure the body so it contains `module`, `operation`, `ids` - Baton needs these to determine the event type (see [Payload format](#payload-format-and-normalization)). For example: `module=Deals`, `operation=insert`, `ids=${Deals.Deal Id}`.
6. Save. Repeat for the modules/operations you need (Contacts, Leads, …).

> If your Zoho plan doesn't give full control over the body of the standard webhook - use a **Custom Function (Deluge)** with `invokeurl`: it lets you set both the `Authorization` header and a JSON body.

### Step 3. Create an Automation Rule in Baton

1. **Automations** page → **Create Rule**.
2. **Source**: Zoho CRM.
3. **Event type**: e.g. `deals.created` (or the wildcard `deals.*`).
4. Select the target workflow → save and activate.

### Step 4. Testing

```bash
# username:password in the header - this is base64("baton-zoho:your-password")
curl -X POST https://your-domain.com/api/webhooks/app/YOUR_WEBHOOK_KEY \
  -H "Content-Type: application/json" \
  -H "Authorization: Basic $(printf 'baton-zoho:your-password' | base64)" \
  -d '{ "module": "Deals", "operation": "insert", "ids": ["12345"] }'
```

Expected response:
```json
{ "received": true, "eventId": "..." }
```

Rejection checks ([app.ts:365-420](../baton/src/routes/webhooks/app.ts#L365-L420)):
- no `Authorization` header → `401 { "error": "Missing Authorization header" }`
- wrong username/password → `401 { "error": "Invalid credentials" }`
- unknown `webhookKey` → `404`
- app deactivated → `403`

### How Basic Auth verification works

From [app.ts:365-420](../baton/src/routes/webhooks/app.ts#L365-L420):
1. The `Authorization: Basic <base64>` header is read.
2. It is decoded into `username:password` (colons in the password are supported - the first colon is used as the separator).
3. Username and password are compared **separately**, each one timing-safe (`crypto.timingSafeEqual`, length check first).
4. Any mismatch → `401`.

## Supported event types

In the UI catalog ([app-catalog.ts:150-157](../baton/src/lib/app-catalog.ts#L150-L157)) the App Webhook shows:

| Event Type | Description |
|------------|-------------|
| `deals.created` / `deals.updated` | Deals |
| `contacts.created` / `contacts.updated` | Contacts |
| `leads.created` | Lead created |
| `leads.converted` | Lead converted |

This is just the list for UI selection. The actual normalization is done by the Zoho connector, so **any** `module.operation` works (e.g. `accounts.created`, `vendors.updated`, `leads.deleted`) - it's enough for the body to contain `module`, `operation`, `ids`.

---

## Payload format and normalization

The body Baton expects (at minimum):
```json
{ "module": "Deals", "operation": "insert", "ids": ["12345"] }
```

An alternative v2 format (also supported by [extractEventInfo](../baton/src/services/connectors/zohocrm.connector.ts#L219)):
```json
{ "query_params": { "module": "Accounts", "operation": "insert" }, "body": { "ids": ["acc-1"] } }
```

The event = `<module>.<operation>` in lowercase. Zoho operations are normalized:

| Zoho `operation` | Baton |
|------------------|-------|
| `insert` | `created` |
| `update` | `updated` |
| `delete` | `deleted` |
| `convert` | `converted` |

`recordId` is taken as the first element of `ids`.

---

## Caveats and gotchas

- **The body must contain `module`/`operation`/`ids`.** Otherwise Baton can't determine the event type. Configure the webhook body in Zoho accordingly.
- **You make up the credentials.** The Basic Auth username/password is not your Zoho account login; you set them yourself and enter them identically in Baton and in Zoho.
- **Idempotency.** Repeated deliveries are dropped in `storeWebhookEvent` (`event.id === 'duplicate'` → post-processing is skipped).
